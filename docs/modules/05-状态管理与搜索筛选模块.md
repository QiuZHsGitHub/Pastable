# 05 状态管理与搜索筛选模块

## 模块定位

负责全局 UI 状态集中管理、搜索节流执行、分类筛选与展示列表输出，是“数据到界面”的状态中枢。

## 涉及文件

- `Pastable/Core/AppState.swift`
- `Pastable/Core/SearchService.swift`
- `Pastable/Core/Throttler.swift`

## 核心能力

### 1) 全局状态管理（`AppState`）

主要 `@Published` 状态：

- 面板与输入：`isPanelVisible`, `searchText`, `searchFocusRequest`
- 列表结果：`filteredItems`, `shouldScrollToTop`
- 设置页：`settingsTab`
- 分类筛选：`selectedCategory`

`AppState` 作为单例共享，供主面板与设置/菜单动作联动。

### 2) 列表同步与去重

- `updateItems(_:)` 接收 SwiftData 查询结果。
- 按 `persistentModelID` 做防御性去重（规避 SwiftData 偶发重复实例）。
- 同一 ID 冲突时保留时间更新的实例。
- 更新后立即重算搜索结果。

### 3) 搜索节流

- 监听 `$searchText` 变化。
- 使用 `Throttler(minimumDelay: 0.2)` 避免高频搜索。
- 节流后在主线程执行 `performSearch(query:)`。

### 4) 搜索策略（`SearchService`）

支持两种模式：

- `exact`：`localizedCaseInsensitiveContains`
- `fuzzy`：
  1. 先做同样的快速包含匹配。
  2. 无命中时回退到 `smartMatch`（按字符顺序近似匹配）。

### 5) 分类过滤与展示输出

`displayItems` 先应用搜索结果，再按分类过滤：

- `All`
- `Code`
- `Links`
- `Others`（图片/文件）

文本分类会排除 code/link/image/file，归入普通文本。

## 对外接口

- `updateItems(_:)`
- `displayItems`
- `searchMode`（`@AppStorage("searchMode")`）

## 依赖关系

- 上游：`ContentView` 将 `@Query items` 同步到 `AppState`。
- 下游：`HeaderView/SearchBar/CardList` 消费状态。
- 配置来源：`GeneralSettingsView` 修改 `searchMode`。

## 已知约束

- 当前搜索仅基于 `item.title`，未覆盖全文字段（如纯 RTF 原文、应用名等）。
- 分类值为字符串常量，未封装为 enum。
- `Throttler` 使用简化延迟策略，未区分“leading/trailing”策略。
