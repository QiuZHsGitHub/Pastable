# Pastable 自动化测试方案

> 本文是本次「自行设计测试用例、全面覆盖、跑自动化」的交付说明。
> 逻辑层测试位于 `Tests/PastableTests/`，一键入口见 [`tools/testing/run-tests.sh`](../../tools/testing/run-tests.sh)。

## 1. 目标与分层

| 层级 | 手段 | 目的 | 是否自动化 |
|------|------|------|-----------|
| L1 纯逻辑 | XCTest 单元测试 | 哈希、检索、分类、主题、错误文案等纯函数与模型规则 | ✅ |
| L2 组件集成 | XCTest + 内存 SwiftData + 独立 NSPasteboard | 去重、裁剪、保留期、剪贴板归一化/回写、缓存、延迟写入 | ✅ |
| L3 静态资源契约 | XCTest 扫描源码与 `Localizable.strings` | 多语言 key 对齐、占位符、源码引用完整性 | ✅ |
| L4 构建与启动 | `xcodebuild` + 启动冒烟脚本 | 真实 App 产物能编译、启动、初始化数据库 | ✅（`--smoke`） |
| L5 端到端体验 | 真实 App + macOS Accessibility API + 文档夹具 | 呼出、搜索、筛选、键盘/鼠标选择、回贴、设置、持久化、明暗/多语言、截图与耗时 | ✅（`--e2e`） |
| L6 人工/UI | 手工体验 | 视觉打磨、动画手感、StoreKit 弹窗、CloudKit 实网 | ❌（见第 8 节） |

逻辑层测试不读写真实剪贴板历史：SwiftData 使用 `inMemory: true`；需要落盘的用例使用临时目录；NSPasteboard 使用每次新建的命名剪贴板并 `releaseGlobally()`。

端到端测试使用独立 bundle id `com.qzh.Pastable.e2e`、临时 SwiftData 目录和临时偏好域，结束时恢复系统剪贴板；只驱动 Debug 构建的测试实例，不修改用户正在运行的 App 数据。

## 3. 本次补强的重点场景

### 3.1 边界与异常
- 空字符串 + 图片表示时，哈希必须落到 `image:` 而不是 `text:`。
- 只有未知类型 / 空 payload 时哈希为空，存储走「最近 200 条 + `supersedes`」兼容路径。
- 存储条数设为 0/负数时仍保留至少 1 条；全部置顶时裁剪不会误删；保留期为 0 时清理不删除。
- 数据目录被占成目录（模拟损坏库）时，应改名备份并重建可用库。
- 面板命中测试覆盖 alpha=0.01、零尺寸、半开区间边界、缺字段、跨应用窗口。

### 3.2 组合行为
- 搜索词 + 分类联动（标题命中 vs 正文命中）。
- 搜索模式下「精确模式拒绝子序列」「模糊模式允许正文子序列」。
- 剪贴板「图片 + 文本」时的采集与归一化、关闭图片保存时文本伴生项也不入库。
- 自动维护暂停后历史继续增长，恢复后由手动/启动维护一次收敛。
- 历史超过 120 条（用例用 135 条）时首屏只物化 120 条，键盘移动或滚动到窗口尾部才扩展。

### 3.3 契约与回归
- `NSLocalizedString` 源码中出现的字面量 key 必须存在于 `en.lproj`；`category.*` 动态 key 单独校验。
- 高亮窗口只对 8000 字符搜索区生效，超出后不再显示「伪命中」。
- 缓存只读命中不触发 loader；延迟写入在 `flush` 前不得改模型。

## 4. 执行方式

```bash
# 1) 只跑逻辑层全量回归
swift test

# 2) 一键入口（推荐）：2 轮逻辑回归 + Xcode 构建 + 启动冒烟 + 端到端
./tools/testing/run-tests.sh --repeat 2 --smoke --e2e

# 3) 只做启动冒烟（需先构建）
./tools/testing/smoke-launch.sh /tmp/PastableDerived/Build/Products/Debug/Pastable.app

# 4) 只跑端到端体验（真实窗口，会短暂占用前台）
./tools/testing/e2e/run.sh

# 5) 生成 llvm-cov 覆盖率报告
./tools/testing/coverage.sh
```

端到端测试需要图形会话、辅助功能与屏幕录制权限；详见
[`tools/testing/e2e/README.md`](../../tools/testing/e2e/README.md)。

日志：`build/test-reports/unit-*.log`、`build-*.log`、`smoke-*.log`。

启动冒烟使用 `mktemp` 临时目录作为 `PASTABLE_STORAGE_DIR`，确认进程存活且创建 `Storage.sqlite` 后立即退出，不打开面板、不写入真实历史。

### 5.1 测试中确认的现状行为（非缺陷，已用用例固化）

1. 单个 `file://` URL 会同时命中链接检测，因此单文件卡片也会出现在「链接」分类；多个文件用换行连接后不再被当成一整条链接，只落在「媒体」分类——分类之间允许重叠。
2. HTML 转纯文本预览时 `NSAttributedString` 会保留尾部换行，卡片展示前会自行裁剪。
3. 评分策略在用户跳过早期阶段时，会在 90 天后直接滚到「已达到的最高阶段」，但最高阶段不会重复。
4. 保存类型开关是「整条剪贴板快照」级别的：关闭图片/文件保存时，同一快照中的文本伴生项也不会入库，避免产生无意义的半截记录。

## 7. 端到端体验测试发现与修复

### 7.1 P1（已修复）：面板打开后键入被丢弃

**修复前现象**：在文档中正常打字时打开面板，继续键入的字符既没有进入文档，也没有进入搜索框；Esc 关闭后输入立即恢复。Debug 1.2.1 与本机已安装的 1.2.0 均复现。

**历史证据**（修复前）：

```
[fixture clicked]  doc=""
[typed BEFORE]     doc="BEFORE"
[after hotkey]     panel=true, frontmost=PastableE2EFixture
[typed AFTER]      doc="BEFORE", search=""      ← 键入丢失
[after escape]     doc="BEFORECLOSED"           ← 关闭后恢复
```

**根因**：`openPanel()` 调用 `NSApp.activate` + `panel.makeKey()` + `makeFirstResponder(nil)`，面板成为 key window 却没有文本首响应者；`ContentView` 的 local monitor 只处理导航键，其余事件原样返回，此时 App 未真正激活，事件被系统丢弃。

**修复内容**：

- 打开面板不再激活 App、不再 `makeKey`；文档继续持有键盘。
- 新增 CGEvent 全局键盘 tap：仅截获 Esc / Enter / 左右方向键 / ⌘1…9 / ⌘⌫ / ⌘⇧F，可打印字符原样透传给文档；需要「辅助功能」与「输入监控」权限，缺少输入监控时不安装 tap（鼠标仍可用，键入不会被抢）。
- 搜索框首击由 `FloatingPanel.sendEvent` 消费；激活完成后延迟发出 SwiftUI focus，避免 AppKit 在点击中途把 App 置回非激活。
- 分类/空白区触发 `.blur` 时释放面板焦点，重新激活原文档。
- 卡片首击通过 `ShelfHostingView.acceptsFirstMouse` 保持一次点击生效。
- 粘贴/删除统一到 `AppDelegate`，local monitor 与全局 tap 共用一套实现。

**修复后验证**：

- `typing keeps working while the shelf is open` — **PASS**
- `category click returns keyboard focus to the document` — **PASS**
- 焦点场景仍验证：打开面板不抢前台、键入进入文档、Esc 后继续输入
- 端到端最终 **112/112 通过，0 已知问题**

### 7.2 P3（已修复）：多文件卡片标题不稳定

**修复前现象**：同一组两个文件（`Q4 launch plan.md` + `budget-2026.csv`）在不同种子库中，卡片标题有时显示前者、有时后者。

**根因**：`CardCell.cardTitle` 重新读取 `item.fileURLs.first`，而 SwiftData 的 `contents` 对多关系顺序没有保证；初始化时按复制顺序生成的 `title` 被覆盖。

**修复**：卡片优先使用持久化的 `item.title`（初始化时按复制顺序生成，重启后稳定）；仅在没有标题的旧记录上回退到 `fileURLs.first`。

**验证**：E2E 新增严格断言 `multi-file card title follows copy order`，并校验重启后标题不变；均通过。

### 7.3 回归保护

- 两项修复对应的检查都是普通断言，不是 `KNOWN ISSUE`；一旦回退，`run-tests.sh --e2e` 会以非 0 退出。
- `knownIssues` 当前为 0；`checkKnownIssue` 仍保留给未来确认的产品问题使用。

## 8. 不纳入自动化的部分（及原因）

| 项目 | 原因 | 替代验证 |
|------|------|---------|
| StoreKit 评分弹窗 | 需要真实 App Store 会话与用户交互 | 只测决策策略与计数持久化 |
| CloudKit 真实同步 | 依赖 Apple ID、网络、entitlement；沙盒/CI 不可控 | 测本地去重合并与开关分支 |
| 辅助功能被拒绝的分支 | 需要 TCC 拒绝状态，已授权会话中难以稳定构造 | 逻辑层覆盖 `paste()` 的开关/权限前置返回；端到端覆盖授权成功时的真实 Cmd+V |
| 输入监控未授权 | 全局键盘 tap 不可用；方向键/Enter 等无法在面板未聚焦时驱动 | 面板仍可鼠标操作，文档键入不被抢；已授权环境由端到端覆盖 |
| 全局快捷键触发 | 本机同时运行已安装版 Pastable，同一组合键会争抢注册 | 端到端用状态栏点击（与真实点击同一条 `togglePanel` 路径） |
| 真实物理键盘 / 输入法 | 自动化使用合成 Unicode 事件，不经过 IME | 逻辑层覆盖文本捕获；端到端覆盖 ASCII 输入 |
| 多显示器 / Space 切换 | 依赖具体桌面拓扑，难以稳定断言 | 窗口几何/层级单测与启动冒烟 |
| 视觉/动画/毛玻璃 | SwiftUI 像素级回归成本高 | 主题 token 与颜色值单测 |
| OCR（Vision） | 识别结果依赖系统模型与语言包 | 只测「无标题图片才调度」等守卫条件 |

## 9. 维护约定

- 用例名使用 `test<行为>_<条件>` 风格，断言失败信息写清业务含义。
- 所有修改 `UserDefaults` 的用例必须在 `tearDown` 恢复原值（参考 `PreferencesTests`）。
- 需要 SwiftData 的用例统一 `Storage(inMemory: true)`；需要 NSPasteboard 的用唯一命名并释放。
- 时间相关逻辑通过注入 `now`（`ReviewPromptPolicy`）或相对时间构造，避免 sleep 与真实时钟。
- 新增本地化 key 时，`LocalizationSourceUsageTests` 会自动拦截漏翻。
- 端到端测试使用 `checkKnownIssue` 记录已确认但未修复的产品问题：修复后自动转 PASS，不需要改测试结构；当前已知问题为 0。
- 端到端用例必须使用独立 bundle id、临时库与临时偏好域，并在退出时恢复系统剪贴板。
